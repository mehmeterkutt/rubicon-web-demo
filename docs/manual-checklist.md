# Manual checklist

Run before every SDK release, with the demo app and the fake backend, in Chrome, Firefox and
Safari, and record the result in the release pull request and under "Last run" (SDK implementation
plan, step 9.3). Setup: README "Hostnames" and "Run it" (the `/etc/hosts` line, `pnpm server`, then
`pnpm build && pnpm preview`, the built app, which the back/forward cache needs); open
`http://a.rubicon.test:4173/`; the Server tab must say "reachable". Start from the defaults
(Settings > Defaults and reload); a settings change is Settings > Save and reload. The Logs tab
shows the SDK's lines (debug level by default) and the observer's queued, sent and dropped updates;
the Server tab shows what arrived (Received events) and every request with its origin and gzip flag
(Requests).

The Playwright scenario suite (`e2e/scenarios/`, `pnpm e2e`) drives the same pages and buttons in
Chromium, Firefox and WebKit against a fake backend of its own per worker, with Playwright's clock
where a wait is long. The last column names its test (`<spec>`, `row N`) or says why the row needs a
person. A row the suite covers still belongs to the release run in the real browsers, where it is
quick; the rows marked manual are the ones only a person can do.

## Measurements that set constants

Each result goes into section 15 of the SDK plan as a row with the date, the device, the browser
and its version (the SDK session records it; this repository only notes the run below). Steps 1.4
(Firefox at close) and 8.1 (the 500 ms window of the routers) were measured in the SDK's own suite
and need no row here. None of these can be done by Playwright: they need a real device, a real
network or a person's browser.
